# Подключение 1С управляющей компании к «УК-инциденты»

Жители ваших домов отправляют заявки в мини-приложении MAX. Ваша 1С забирает их по HTTP
и отправляет обратно смену статуса — жители получают уведомления. Ваша 1С всегда
клиент: публиковать HTTP-сервис наружу не нужно.

Адрес сервиса: `https://nerionapp.ru`. Контракт: `backend/openapi.yaml`, операции с тегом
`integration`. Все запросы и ответы — JSON в UTF-8, ошибки — `{ "code": "...", "message": "..." }`.

## 1. Получить ключ

1. Войдите в кабинет УК (ИНН организации и пароль сотрудника АДС). Доступ есть у УК с
   действующей лицензией в реестре ГИС ЖКХ.
2. Раздел «Интеграция» → «Выпустить ключ», укажите название (например, «1С: офис на Баумана»).
3. Скопируйте ключ `uk_live_…` сразу — повторно его не показать. У нас хранится только его хэш.
4. Отзыв — там же. Отозванный ключ перестаёт работать на следующем запросе. Активных
   ключей у организации — не больше 10.
5. Если лицензия организации в реестре ГИС ЖКХ перестала действовать, все её ключи
   отвечают `401` до продления лицензии.

Ключ передаётся в каждом запросе:
```
Authorization: Bearer uk_live_…
```
Ключ действует от имени диспетчера «1С-интеграция» вашей организации: он видит только
ваши дома и заявки. Не больше 10 запросов в секунду на ключ.

Пока у организации есть активный ключ, заявки её домов не передаются в другие
подключённые системы УК — источником статусов становится ваша 1С. Заявки, которые уже были
переданы в другую систему до выпуска ключа, продолжают синхронизироваться с ней.

## 2. Схема обмена

Регламентное задание раз в 1–5 минут:

1. `GET /api/uk/incidents/changes?cursor=<сохранённый>&limit=100` — заявки, созданные или
   изменённые после курсора. Первый раз — без `cursor`: придут все заявки ваших домов.
2. Для каждого элемента найдите документ «Заявка» по `id` (например, `inc_42`) и создайте
   или обновите его. Элементы могут повторяться — обработка должна быть идемпотентной.
3. Сохраните `nextCursor` (например, в регистре сведений). Если пришло ровно `limit`
   элементов — сразу запросите следующую страницу.

Курсор выдаётся только закоммиченным изменениям и только растёт: изменение не может
появиться «позади» уже сохранённого курсора, поэтому пропусков не бывает.

Поля заявки: `id`, `houseId`, `houseAddress`, `title`, `description`, `category`,
`severity` (`critical` | `warning`), `status`, `createdAt`, `dueAt` (срок по SLA),
`affectedCount` (сколько жителей затронуто), `confirmedCount`, `mergedCount`,
`reporterName`, `photos` (`[{ id, url }]`, `url` относительный — добавьте к нему адрес
сервиса, ключ для скачивания не нужен), `mergedIntoId`, `updatedAt`.

### Статусы

```
pending → accepted → in_progress ⇄ verifying → done
```

| Статус | Смысл | Кто ставит |
|---|---|---|
| `pending` | новая заявка, жители дома её ещё не видят | мы |
| `accepted` | принята диспетчером | вы |
| `in_progress` | в работе | вы |
| `verifying` | вы считаете, что починили; мы просим жителей подтвердить | вы |
| `done` | закрыта | вы (из `verifying`) или мы (жители подтвердили; склейка) |
| `false_alarm` | ложный вызов | только мы |

Смена статуса:
```
PATCH /api/incidents/{id}/status
{ "status": "accepted" }
```
`pending` можно перевести только в `accepted`. Между `accepted`, `in_progress`, `verifying`
— в любую сторону. `done` — из `verifying`; из `done` — только обратно в `verifying`.
Недопустимый переход → `422`: перечитайте ленту, статус уже изменили.

Заявка со `status = done` и заполненным `mergedIntoId` — дубликат, склеенный в заявку
`mergedIntoId`; закройте её у себя со ссылкой на главную.

### Остальные операции

| Операция | Запрос |
|---|---|
| Текущая очередь с сортировкой по важности | `GET /api/uk/queue?offset=0&limit=100` |
| Склеить дубликаты одного дома | `POST /api/uk/incidents/merge` `{ "targetIncidentId": "inc_1", "sourceIncidentIds": ["inc_2"] }` |
| Объявить плановые работы | `POST /api/uk/events` `{ "houseId", "reason", "responsible", "entrance", "riser", "scheduledFrom", "scheduledTo" }` |
| Плановые работы дома | `GET /api/events?houseId=h_1` |

## 3. Коды ответов

| Код | Когда | Что делать |
|---|---|---|
| `200`/`201`/`204` | успех | — |
| `400` | неверный запрос (формат, `cursor`) | исправить запрос |
| `401` | ключ неизвестен, отозван или лицензия недействительна | остановить обмен, сообщить администратору |
| `403` | операция недоступна ключу | проверить настройку |
| `404` | заявка или дом не вашей организации | пропустить |
| `422` | недопустимый переход статуса | перечитать ленту |
| `429` | больше 10 запросов в секунду | повторить через секунду |
| `5xx` | ошибка у нас | повторить с паузой, курсор не менять |

## 4. Пример на встроенном языке 1С

```bsl
Функция ВызватьСервис(Метод, Путь, Тело = Неопределено) Экспорт

	Соединение = Новый HTTPСоединение("nerionapp.ru", 443, , , , 30, Новый ЗащищенноеСоединениеOpenSSL);
	Заголовки = Новый Соответствие;
	Заголовки.Вставить("Authorization", "Bearer " + Константы.КлючУКИнциденты.Получить());
	Заголовки.Вставить("Accept", "application/json");
	Запрос = Новый HTTPЗапрос(Путь, Заголовки);

	Если Тело <> Неопределено Тогда
		Запрос.УстановитьЗаголовок("Content-Type", "application/json");
		Запись = Новый ЗаписьJSON;
		Запись.УстановитьСтроку();
		ЗаписатьJSON(Запись, Тело);
		Запрос.УстановитьТелоИзСтроки(Запись.Закрыть(), КодировкаТекста.UTF8, ИспользованиеByteOrderMark.НеИспользовать);
	КонецЕсли;

	Ответ = Соединение.ВызватьHTTPМетод(Метод, Запрос);
	ТекстОтвета = Ответ.ПолучитьТелоКакСтроку(КодировкаТекста.UTF8);

	Результат = Новый Структура("Код, Данные", Ответ.КодСостояния, Неопределено);
	Если ЗначениеЗаполнено(ТекстОтвета) Тогда
		Чтение = Новый ЧтениеJSON;
		Чтение.УстановитьСтроку(ТекстОтвета);
		Результат.Данные = ПрочитатьJSON(Чтение);
		Чтение.Закрыть();
	КонецЕсли;
	Возврат Результат;

КонецФункции

Процедура ЗагрузитьЗаявки() Экспорт

	Курсор = РегистрыСведений.НастройкиОбменаУКИнциденты.Курсор();
	Пока Истина Цикл
		Путь = "/api/uk/incidents/changes?limit=100";
		Если ЗначениеЗаполнено(Курсор) Тогда
			Путь = Путь + "&cursor=" + Курсор;
		КонецЕсли;
		Результат = ВызватьСервис("GET", Путь);
		Если Результат.Код = 401 Тогда
			ВызватьИсключение "Ключ УК-инциденты отозван или неверен";
		ИначеЕсли Результат.Код <> 200 Тогда
			Возврат;
		КонецЕсли;

		Для Каждого Элемент Из Результат.Данные.items Цикл
			Документы.ЗаявкаЖителя.ЗагрузитьИзСервиса(Элемент);
		КонецЦикла;

		Курсор = Результат.Данные.nextCursor;
		РегистрыСведений.НастройкиОбменаУКИнциденты.СохранитьКурсор(Курсор);
		Если Результат.Данные.items.Количество() < 100 Тогда
			Прервать;
		КонецЕсли;
	КонецЦикла;

КонецПроцедуры

Функция СменитьСтатус(ИдентификаторЗаявки, Статус) Экспорт

	Тело = Новый Структура("status", Статус);
	Результат = ВызватьСервис("PATCH", "/api/incidents/" + ИдентификаторЗаявки + "/status", Тело);
	Возврат Результат.Код = 200;

КонецФункции
```

`ЗаявкаЖителя.ЗагрузитьИзСервиса` и `НастройкиОбменаУКИнциденты` — объекты вашей
конфигурации; названия условные. PATCH отправляется через `HTTPСоединение.ВызватьHTTPМетод`,
его нет в старых релизах платформы 8.3 — если метода нет, обновите платформу.

## 5. Проверка без 1С

```bash
KEY=uk_live_...
curl -s -H "Authorization: Bearer $KEY" "https://nerionapp.ru/api/uk/incidents/changes?limit=5"
curl -s -X PATCH -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"status":"accepted"}' https://nerionapp.ru/api/incidents/inc_1/status
```

Выпуск ключа без интерфейса кабинета (токен сотрудника — из `POST /api/auth/esia-mock`):
```bash
curl -s -X POST -H "Authorization: Bearer $JWT" -H "Content-Type: application/json" \
  -d '{"name":"1С офис"}' https://nerionapp.ru/api/uk/api-keys
```
